# D2D Condition Labeling

この文書は、このプロジェクト固有の実装パターン集である。D2D resource 周りで条件式の意味を読みやすく保つための判断をまとめる。

## 状態変化を判定する場合

状態変化の条件式は、`bool isViewportResized` のような名前付きの値に閉じ込める。

これにより、後続の `if` は条件式の詳細ではなく「何を判定しているか」を読むだけで理解できるようにする。

## 条件式が複数箇所に散る場合

同じ条件式が複数の method に散り始めたら、どの method や class がその概念を所有するべきかを見直す。

例えば viewport サイズ変更の判定を `ViewportGeometryCache::syncViewportSize` に集約している場合、`get` では同じサイズ比較を繰り返さない。`get` は「resource があれば返す。なければ作る」という取得責務だけを持つ。

## 別境界の判定結果に依存しない場合

別 provider の状態更新結果に、自分の cache invalidation を直接依存させない。

境界が違う場合は、それぞれの provider が自分の状態変化を自分で検出する。戻り値で偶然つながる形にすると、後からどちらの責務なのか読み取りにくくなる。
